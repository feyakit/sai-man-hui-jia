## 1. 产品定位

- 名称：**塞满回家**；副标题：为老家接回更多人；口号：年货塞不下（见 `config/brand.ts`）。
- 一句话：春运前把年货一件件塞进后备箱，最后一件放进去，“砰”地关上盖子回家。
- 核心情绪：**亲手把年货恰好塞满**的满足感。所有工作优先服务这一点。
- 平台：先做手机竖屏 H5（Cocos Web Mobile），手感验证后移植微信小游戏。

### 1.1 视觉基调
春节红配米白，暖色卡通插画，物品一眼能认出。色板以 v1.1 品牌色为准（现有代码里的 `#9E2D29`、`#FFC977` 等改为下表）：

| 用途 | 色值 |
| --- | --- |
| 春节红（按钮、车身、标题） | `#D7332B` |
| 暖黄（点缀、旋转按钮、描边） | `#F6C343` |
| 米白（背景） | `#FFF6E5` |
| 深棕（描边和文字） | `#4A2C1A` |
| 网格线 | `#E8D9BF` |
| 合法落点 | `#4CAF50`，50% 透明 |
| 非法落点 | `#E53935`，50% 透明 |

风格：2D 扁平卡通加一点 2.5D 质感（统一左上光源、柔和投影、高光），统一深棕描边，不做 3D。参考效果图由产品方另行提交到 `docs/mockups/`。

## 4. 竖切版 V1（当前阶段）

### 4.1 目标
手机浏览器打开链接，30 秒内觉得“爽”。内容：第 1 关、第 2 关、“妈妈又塞了一件”模式。

### 4.2 屏幕布局（竖屏 750×1334 设计坐标）
自上而下：
1. **顶栏**（约 0–200）：关卡名与车型、倒计时、“已装 n / N 件”、设置按钮（音效、震动开关）。
2. **后备箱区**（约 200–860）：车尾插画 + 打开的后备箱，网格在箱内。格长 = `min(110, 可用宽/列数, 可用高/行数)`，向下取整。禁放格（轮拱等）用插画遮住或画成明显的斜纹，不能像空格。
3. **托盘区**（约 880–1150）：待装行李，**不滚动**。
4. **操作栏**（约 1170–1290）：`旋转`（大按钮，至少 160×120，最显眼）、`撤销`、`重开`。
- 适配：内容按宽度缩放；高于 16:9 的屏幕把多余高度分给后备箱区；读取安全区，顶栏和操作栏不得进入刘海或底部手势条。
- 只支持竖屏。横屏时显示“请竖屏游玩”遮罩，计时照常。

### 4.3 托盘
- 所有未放置行李一屏摆下，按关卡文件里的顺序排列。
- 布局算法：先尝试一行；若单件缩略格长 < 28px 则改两行；两行仍放不下就整体等比缩小，下限 20px/格。12 件时必须两行内放下。
- 每件缩略图按当前朝向显示，统一格长，形状一眼可辨。
- 托盘里的空位不留洞：放进后备箱的物品从托盘移除，其余件不重新排序（位置保持稳定，避免误抓）；拖回托盘的物品回到它原来的槽位。
- 被选中的物品有金色描边。

### 4.4 选中与拖拽
| 操作 | 结果 |
| --- | --- |
| 轻点托盘或后备箱里的物品 | **选中**，不旋转，不移动 |
| 轻点空白处 | 取消选中 |
| 按住物品并移动超过 8px | 拿起，进入拖动 |
| 拖动中 | 物品放大到后备箱格长的 1.05 倍，加投影；物品**整体中心**保持在手指上方 `max(1.2 格, 120px)`，不被手指挡住 |
| 拖到后备箱上方 | 实时显示落点预览：合法绿色，非法红色 |
| 合法处松手 | 落下，播放落位反馈（4.7） |
| 非法处或后备箱外松手 | 来自托盘的回托盘原位；来自后备箱的回后备箱原位。180ms 缓动飞回，播放“不行”音效 |
| 从后备箱拖到托盘区松手 | 归还托盘 |
| 拖动中第二根手指 | 只有按在“旋转”按钮上才生效，其余忽略 |
| 系统打断（来电、切后台、窗口尺寸变化、计时结束） | 取消拖动，物品回原位，不丢件 |

- 抓取判定：手指落在物品任一格的包围区内（含格间缝）都算抓到这件，不要求落在像素上。
- 拖动跟手：手指移动当帧更新位置，不加平滑延迟。

### 4.5 吸附规则
- 用“物品左上格应落在哪一格”做**就近取整**（现有 `snapToGrid` 的算法），只看最近的那一个位置，**不**自动搜索远处的合法位置。
- 预览只在物品至少一半格子落在后备箱网格范围内时显示；否则不显示预览，此时松手按非法处理。
- 碰撞规则沿用 `StageSession.canDrop`：不出界、不重叠、不覆盖禁放格。

### 4.6 旋转
- 只有“旋转”按钮能旋转，每按一次顺时针 90°。禁止镜像，禁止双指旋转手势。
- 按钮状态：无选中物品时置灰；有选中或正在拖动时高亮。
- 拖动中按：手里的物品立即转向，预览随之刷新。
- 选中托盘物品时按：托盘缩略图转向。
- 选中后备箱里的物品时按：以原锚点尝试旋转；放不下则**保持原样**，物品红色抖动 200ms，播放“不行”音效。（替换现有“放不下就送回托盘”的行为。）
- 旋转有 120ms 转动动画，逻辑状态立即生效。

### 4.7 反馈
| 事件 | 画面 | 声音 | 震动 |
| --- | --- | --- | --- |
| 拿起 | 放大、投影 | `pickup` | 10ms |
| 合法落下 | 压扁回弹：纵向 0.85 → 1.05 → 1.0，共约 220ms | `drop`（“咚”） | 20ms |
| 非法松手 | 飞回原位 | `invalid` | 无 |
| 旋转 | 转动动画 | `rotate` | 无 |
| 撤销 / 重开 | 物品飞回 | `undo` | 无 |
| 倒计时 ≤ 10 秒 | 数字变红、轻微跳动 | 每秒 `tick` | 无 |

- 设置里有“音效”“震动”两个开关，默认开，存 `localStorage`。
- 震动用 `navigator.vibrate`，不支持时静默跳过。
- 音频文件缺失或加载失败：静默，不报错，不影响游戏。

### 4.8 撤销与重开
- 撤销：回退一步（放置、拿出、旋转都算一步），不限步数，任何时候都不丢件。撤销后选中状态清空。
- 重开：二次确认（“重新装车？”），清空后备箱，所有物品回托盘初始朝向，计时重置。
- 时间到：盘面冻结，弹出“时间到 · 再装一次”，按钮重开当前关。

### 4.9 塞满结算（最重要的一段）
最后一件合法落下后，依次播放（总长约 2.5 秒，可点击屏幕跳到最后一帧）：
1. 0–300ms：最后一件的落位反馈照常播放。
2. 300–700ms：后备箱盖从上方落下关上，`trunk_slam`（“砰”），震动 40ms。
3. 700–1000ms：车身下沉约 12px 再回弹一半（东西很重）。
4. 1000–1600ms：尾灯闪两下，同时 `horn` 播放两次（“嘀嘀”）。
5. 1200–2500ms：彩纸从顶部洒落，屏幕中央出现大字“**塞满了！回家！**”。
6. 2500ms 后出现按钮：第 1 关后为“下一关”；第 2 关后为“再来一次”和“试试妈妈模式”；妈妈模式后为“再来一次”和“回第 1 关”。
- 彩纸粒子 ≤ 120 个，结束后全部回收。

### 4.10 关卡
所有 V1 关卡放在 `client/assets/resources/levels/v1/`，每个关卡文件都要在测试里用 `dlx.solve` 证明有解，并把一个解写入 `tests/fixtures/v1/<关卡名>.solution.json`（不打进客户端包）。

**第 1 关（新手）**
- 4–5 件，小车后备箱，无禁放格或 1 个禁放格；可沿用现有 `stage1`（4×3，甘蔗、牛奶箱、两箱白酒）。
- 限时 60 秒。
- 不弹教学弹窗。开局在第一件物品上出现手指动画示意“拖到这里”，玩家第一次触摸后消失。
- 目标：首次玩的人 10 秒内完成第一次放置。

**第 2 关（中等）**
- 10–12 件，大多数人努力一下能过。
- 难度参数写在 `tools/config/v1-levels.json`，改参数后运行 `npm run levels:v1` 重新生成并验解，**不改代码**：

```json
{
  "stage2": {
    "vehicle": "sedan_v1",
    "width": 8, "height": 6,
    "blocked": [[0,5],[7,5]],
    "pieceCount": [10, 12],
    "maxSameShape": 2,
    "maxSixCells": 1,
    "solutionCount": [3, 40],
    "minNodesToFirst": 200,
    "timeLimitSec": 150,
    "randomInitialRotation": true,
    "seed": "v1-stage2-a"
  }
}
```
  以上是起始值，产品方实测后会调。生成失败时报错写清哪条约束没满足。
- 同一形状最多 2 件，物品要有变化，不要再出现 9 个春联礼包。
- 生成结果固定提交成 `stage2.json`，不在运行时随机生成。

**妈妈又塞了一件（独立模式）**
- 入口：第 2 关结算页的“试试妈妈模式”按钮，以及 `?mode=mom` 直达。**普通关卡永远不会触发。**
- 开场一句说明：“妈妈说：再带点东西！”
- 规则：
  - 开局托盘里只有“第一批”行李，后备箱比它们需要的空间大。
  - 第一批全部放进后备箱后（托盘空了），播放妈妈出场：妈妈头像从侧边探出，气泡“等等！还有这个！”，一件新行李（如被子、鱼、鸡鸭笼）掉进托盘，`mom` 音效。
  - 玩家可能得拿出已放的物品重新排。
  - 共追加 2–3 次；最后一次追加后，所有物品恰好填满后备箱，触发 4.9 结算。
- 必须有解：关卡文件包含 `base` 行李和按顺序的 `extras` 行李；**全部行李合起来恰好填满后备箱且用 `dlx.solve` 验证有解**（任何子集因此也必然放得下）。测试里强制检查。
- 默认不限时（`timeLimitSec: 0` 表示不限时），配置可改。
- 撤销不能撤回妈妈的追加；重开回到第一批。
- 配置也写在 `tools/config/v1-levels.json` 的 `mom` 字段里（车型、`base` 件数、`extras` 形状序列、种子）。

**数据结构**
- 扩展 `Level`：增加可选 `mode?: 'normal' | 'mom'`、`extras?: PieceDef[][]`；`stage` 允许 `1 | 2 | 3`（3 = 妈妈模式）；`timeLimitSec` 允许 0。`parseLevel` 的面积校验改为“base + 全部 extras = 可用格数”。
- 旧关卡文件（`demo.json`、七天关卡）必须继续能解析和通过原有测试。
- 新增车型 `sedan_v1` 写入 `vehicles.ts` 时不得改动已有六种车型的数据。

- 尺寸 = 该形状在朝向 0（`shapes.ts` 原始定义）的包围盒 × **每格 128px**。

- 一张图对应朝向 0。其他朝向由代码整图旋转得到，所以图上不要有必须保持正向的文字。

**占位兜底（代码必须实现）**
- 某张图不存在或加载失败：用现有色块画法画出该形状，并在中间写物品名（`items.ts` 的 `name`）。游戏照常运行，不报错。
- V1 交付时仓库内必须有一套**程序生成的占位 PNG**（按上表尺寸、透明底、彩色格子 + 物品名），由 `npm run art:placeholders` 生成到同一目录。产品方的正式图直接覆盖同名文件。
- 新增 `npm run art:check`：检查每张图存在、尺寸正确、非占用格完全透明（alpha = 0），不合格列出文件名和原因。CI 跑这个检查。

### 4.12 性能
- 目标 60fps，低端机不低于 45fps。
- 拖动中只移动被拿起物品的节点和预览节点，**不得每帧重画整个盘面**。每件行李一个 `Sprite` 节点，网格背景只在开局或尺寸变化时画一次。
- 拖动和结算动画期间不在每帧分配新对象（`Color`、数组、闭包）。
- 首屏资源（第 1 关用到的图 + UI）加载完成到可操作 ≤ 3 秒（4G 网速模拟）。

### 4.13 不做的事（V1 范围外）
页面流程（启动页、首页、省份选择）、每日关卡、排行榜、分享、登录、云端、广告、道具、微信适配。都在 M5 以后。

## 5. 验收规则（所有阶段通用）

### 5.1 每个 PR 必须附
1. **改了什么、没改什么**：逐条对照任务里的验收项，标明“通过 / 未做 / 部分”，不得把未完成写成完成。
2. **CI 全部绿灯**：`verify` 和 `Build Cocos Web Mobile`（`build` + `browser`）。红灯的 PR 不验收。附对应 Actions 运行链接。
3. **截图和录屏**：由 CI 浏览器验收产出，存在 artifact `web-mobile-browser-evidence`。PR 描述列出本任务新增的截图文件名，说明每张证明什么。录屏用 Playwright `recordVideo`，手机视口（Pixel 7 与 iPhone SE 各一）。
4. **试玩方式**：CI 的 `trunk-home-web-mobile` artifact 链接；如果已配置预览部署（见 5.3），附预览链接。
5. **开发记录**：在 `docs/development-log.md` 追加一节，写日期、执行的命令、结果、剩余未验收项、需要人工做的事。

### 5.2 自动化浏览器验收（`tools/cocos/smoke-web-mobile.mjs`）
每个改动交互的任务都要扩展这个脚本，桌面鼠标和模拟触屏都跑。V1 结束时至少覆盖：
- 第 1 关、第 2 关、妈妈模式各通关一次（按 fixtures 里的解操作，只用“旋转”按钮转向）。
- 轻点托盘物品：朝向**不变**，选中状态改变。
- 拖动中按旋转按钮（双触点）：手中物品转向，落下后朝向正确。
- 非法落点：物品回原位，盘面不变。
- 后备箱外松手、从后备箱拖回托盘、撤销、重开（含确认）。
- 托盘：12 件时所有物品的槽位矩形都在托盘区域内、互不重叠，横向滑动托盘不改变任何物品位置。
- 拿起时，物品中心在触点上方至少 120 设计像素。
- 设置开关关闭后不调用 `navigator.vibrate`（用 page 注入的桩函数计数）。
- 时间冻结 10 秒后倒计时正确（沿用现有检查）。
- 页面无 JS 报错。
- 视口：Pixel 7、iPhone SE（375×667）、一台 20:9 高屏（如 412×915）。

### 5.3 预览部署（试玩链接）
- 现有私密试玩页是手工部署，CI 不会更新。
- V1 第一个开发任务里新增一个可选的部署步骤：仓库配置了部署密钥时，每次 PR 的构建自动发布到一个预览地址并把链接写入运行摘要；未配置时跳过，不报错。部署平台由产品方提供密钥后确定，代码里只读取 Secrets，不写死账号。
- 未配置预览时，以 artifact 下载包为准（解压后用任意静态服务器打开 `index.html`）。

### 5.4 真机检查（产品方执行，Codex 提供清单）
每个阶段交付时，Codex 在 PR 里给出本阶段的真机检查清单，产品方在 iPhone Safari 和 Android Chrome 上逐项勾选。V1 清单至少包括：手指不遮挡、无误触旋转、托盘不滑动、快速拖放落点正确、刘海与底部手势条不遮挡按钮、震动可关、拖动流畅无明显卡顿。

### 5.5 禁止事项
- 不得虚报：没跑过的测试不能写“通过”，没有截图的界面不能写“已完成”。
- 不得删除或跳过已有测试来让 CI 变绿；需要改动旧测试时，在 PR 里逐条说明原因。
- 不得提交密钥、生产种子或正式关卡的解。
- 不得在 V1 期间改动 `core/dlx.ts` 的求解算法和已有六种车型的数据，除非任务明确要求。

## 7. 后置阶段（V1 通过后再展开，届时补详细任务）
以下内容保留 v1.1 的设计，作为后续阶段的范围。具体字段、接口、文案以 v1.1 原文（`docs/archive/spec-v1.1.md`）为参考，开工前会出补充规格。

### M5 微信小游戏移植
- Cocos 微信小游戏构建模板，主包与分包配置，主包 ≤ 4MB。
- 平台层抽象：现有 `platform/WebPlatform.ts` 扩展为接口，新增 `WechatPlatform`（时间、存储、震动 `wx.vibrateShort`、音频、安全区 `wx.getSystemInfoSync`）。
- 微信开发者工具和真机（iOS、Android 各一台）跑通 V1 全部内容。
- AppID 从本地配置读取，不进仓库。

### M6 页面流程与玩法外围
- 启动页、首页、转场、正式结算页。
- 选老家省份（`core/provinces.ts` 的 34 项），本地保存。
- 每日车型轮换：沿用 M2 生成器与 HMAC 种子，按上海时区日期（`core/date.ts`）。
- 帮忙模式、分享图生成。
- 道具仅做本地模拟，不接广告。

### M7 微信云端
- 微信登录；全国同一每日关卡；每人每天首次通关为老家“接回一人”；省份榜与连胜。
- 关卡与解分离：客户端只拿关卡，解只在服务端（`levels/solutions/`），云函数校验提交的放置序列（用 `core/validate.ts` 同一套规则）。
- 防作弊：服务端复核解、完成时间下限、提交去重。
- 真实关卡上传：`levels:upload` 去掉 `--dry-run` 限制，接云环境。
- 云环境 ID、生产种子 `LEVEL_SECRET` 只放环境配置。

### M8 广告与道具
- 激励视频换道具（如“提示一格”“加时”），广告位 ID 从配置读取。
- 不影响每日公平关卡的排名口径，具体规则在 M8 补充规格里定。

### M9 上线打磨
- 断网重试、提交去重、埋点。
- 合规：隐私政策、用户协议、未成年人保护提示、游戏版号相关要求（以 v1.1 合规章节为准）。
- 低端机性能复测、包体优化、上线验收清单。

## 8. 协作约定
- 开发由 Codex 完成，产品方（仓库所有者）在 GitHub issue / PR 里用 `@codex` 派任务和验收。
- 每个任务一个分支 `codex/v1-<编号>-<简称>`，从最新的 `work/m1-core` 拉出，开 **draft PR 指向 `work/m1-core`**。验收通过后由产品方合并。
- 一次只做一个任务；做完等验收再开下一个。
- 遇到本文没写清的地方：在 PR 里提问并给出你推荐的做法，按推荐做法继续，不要停工等待。
- Cocos 编辑器只在 CI 里运行；本地无法运行编辑器时，以 CI 结果为准，不得声称“本地已构建通过”。
